A real terminal on Linux machines, plus signed telemetry, uninstall on delete, and version pins.

**Deploy the hub first.** Use hub 1.169.0 or later. The terminal needs it. The rest works from hub 1.166.0.

0.3.0 machines update themselves to this release within about fifteen minutes. Nothing has to be reinstalled.

## The Terminal tab is a real terminal

A Linux machine's **Terminal** tab used to be a box that ran one script at a time and printed what came back. It had no keyboard input, and `cd` was forgotten after each command. `top` printed one frame, anything that asked a question hung, and Ctrl-C did nothing.

It is now the same terminal a Windows PC has: a login shell on the machine, running as root, in the browser.

- **Everything a terminal does works.** Enter, Ctrl-C, Tab completion, arrow keys and history, colour, and full-screen programs like `top`, `htop`, `vim` and `less`. So does anything that asks for input, like `apt` asking to continue or `passwd`.
- **It follows the window.** Resize the browser and a running `top` redraws at the new size.
- **Pick bash or sh** in the **Shell** box. bash is used where it exists.
- **Several at once.** **+** opens another terminal (up to four per operator per machine), and **×** or a middle-click ends one.
- **It survives leaving the page.** Come back from another page or another computer and your shells, their working directories and their scrollback are still there.

**What is recorded:** opening a terminal is in the audit log, naming who, which machine and when, as on Windows. What is typed is not kept. Closing the tab hangs up the shell and everything it started, the way closing a terminal window does.

The one-shot box is still there for a Linux machine on an older agent, and for scripts and favorites, which still run as `run_script`.

## Also in this release

- **Telemetry is signed.** Every report is sent with the machine's own credential, so the hub can refuse readings from anything that is not an enrolled agent. Nothing changes until **Settings → Security → Only accept telemetry from enrolled agents** is turned on.
- **Deleting a device can uninstall its agent.** With **"Also uninstall the agent from this PC"** ticked in Devices, the agent removes itself the next time it reaches the hub. It takes the service, `/opt/fleethub`, `/var/lib/fleethub` and `/etc/fleethub` with it. An older agent re-enrolls instead, and the machine reappears.
- **Version pins are honoured.** **Settings → Fleet** can hold Linux machines at one exact agent version, and a machine on the beta channel follows a stable release that is newer than the newest beta.

## If it misbehaves

- **Check the version.** The machine page should read 0.4.0.
- **The Terminal tab still shows the one-shot box.** The machine is not on 0.4.0 yet, or the hub is older than 1.169.0. The hint under the box says when the agent is the reason.
- **A terminal says "could not open a terminal".** The rest of that line is the reason the machine gave. `journalctl -u fleethub-agent` has the same line, with more detail.
- **Read the log.** `journalctl -u fleethub-agent` logs each terminal opening and closing, with the reason it ended.

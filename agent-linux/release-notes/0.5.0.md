Linux machines can now end and restart processes, install the updates a patch run approves, and report their installed software.

**No hub update is needed.** The console and the patch scheduler decide what to offer from the capability report a Linux machine sends, so every feature below switches on by itself once a machine is on 0.5.0. Machines on 0.4.x keep working as before.

0.5.0 includes everything in 0.4.1. That covers a 0.3.0 machine on beta: until 0.5.0 is promoted to stable, it still needs the one-time line from the 0.4.1 notes before it updates.

## End task and Restart on the Processes card

Right-click a process on a Linux machine's **Processes** card for the same menu a Windows PC has.

- **End task** asks the process to exit (SIGTERM). If it is still running five seconds later, it is killed (SIGKILL). The result says when that was needed, which usually means the program was hung. **Also end the processes it started** ends the whole tree.
- **Restart** restarts the **system service** the process belongs to (`systemctl restart`). Examples are nginx, a database or cron. For anything else, such as a desktop app or a program someone started by hand, Restart refuses and says why. The agent cannot start such a program again the way it was started: the user's session, terminal and environment are not recoverable. Use End task, then start it again from the Terminal tab.
- **What is refused:** pid 1, kernel threads, the system journal, logind, udev, the system bus, every `systemd` (including a user's own), and the FleetHub agent itself. Ending any of them takes the machine or the user's session down.
- **A list that has moved on changes nothing.** If the pid now belongs to a different program than the one you clicked, nothing is ended, and the result names what holds the pid now.

## Patch runs install on Linux

Linux machines were already reporting their available updates. Now an approved patch run installs them, in the maintenance window, like on Windows.

- **Only the updates the run names are installed,** and only those the machine still offers. Nothing else is upgraded.
- **Debian and Ubuntu:** `apt-get install --only-upgrade`.
  - It never stops to ask a question.
  - Configuration files you have edited are kept.
  - If the automatic updater holds the package lock, it waits up to five minutes for it.
  - If a package has left the mirror since the last scan, it refreshes the package index once and tries again.
- **Fedora and RHEL:** `dnf upgrade`.
- **Restarts follow the window's reboot policy.** *If required* restarts when the update needs it, for example a new kernel. That is read from `/run/reboot-required` on Debian and Ubuntu, and from `needs-restarting -r` on Fedora and RHEL. The restart comes with five minutes' warning to anyone signed in.
- **The run closes within seconds of the install.** The machine re-checks its available updates as soon as it finishes and reports them on the next heartbeat. The hub uses that report to mark each update installed or not.

## Installed software

A Linux machine's **Software** section and the report sheet now list what is installed. That is every package in `dpkg` or `rpm`, with version, maintainer or vendor, architecture and install date.

- **Libraries are included,** because "which machines still have OpenSSL 3.0.2" is a question about a library.
- **The list is capped at 2,000 packages,** as on Windows. A larger desktop says it was truncated.
- **Packages removed but not purged** (`deinstall ok config-files`) are not listed.
- **Every installed kernel** gets its own row.
- **Snap and Flatpak apps are not listed yet.**

## If it misbehaves

- **Check the version.** The machine page should read 0.5.0.
- **There is no menu on the Processes card.** The machine is not on 0.5.0 yet.
- **A patch run fails.** The result has the last lines apt or dnf printed. Run `journalctl -u fleethub-agent` on the machine for the rest.
- **The Software section is empty.** Run `dpkg-query -W | head` (or `rpm -qa | head`) as root. If that fails, so does the agent, and the journal says *Software inventory not sent* with the reason.

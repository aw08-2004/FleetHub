## 1.146.0 (2026-10-12)

### ⚠ BREAKING CHANGES

* **devices:** deleting a device now offers **Also uninstall the agent from this PC**, ticked by default, and it needs the `issue_commands` capability as well as the right to delete (a user without it is not offered the box, and the API answers 403 rather than doing a plain delete). A PC removes its agent only if it runs Windows agent 3.44.0 or later; an older agent, or a Linux agent before 0.4.0, re-enrolls and the PC reappears as before. Untick the box to clear the record of a PC that is still in use (#122) (84863fc) (6ab7e7e)

### Features

* **devices:** delete a device and its agent removes itself: the hub keeps the deleted agent's id and token hash, and when that token next calls (seconds later, or whenever a switched-off PC is next on) the refusal says `decommissioned`. Only the holder of the real token is told; any other caller hears `unknown`. The duplicate-serial merge never does this (#122) (84863fc) (09cfabd)
* **devices:** prune each decommissioned-agent record 30 days after the PC was last told and has stopped calling, and after a year for a PC that never called again; an agent whose uninstall keeps failing keeps its record (#122) (4d62751)

### Bug Fixes

* **onboarding:** save the onboarding script into a folder only SYSTEM and Administrators can write to and run it from the file, instead of from memory under `Bypass`, which antivirus read as a dropper, and instead of from the user's `%TEMP%`, which another process of the same user could swap (#122) (eb658dc) (abde6f9) (00230ed)

## 1.192.0 (2026-11-26)

### Features

* **onboarding:** a PC that cannot reach GitHub can now be onboarded. The hub keeps its own copy of the agent releases, the installers and the PawnIO driver, and the onboarding script downloads the installer from the hub. The installers try GitHub first and the hub second for every file. Before, such a PC reached the hub and then failed at *Installing the FleetHub agent* with *Unable to connect to the remote server*
* **onboarding:** everything a PC downloads from the hub is still checked against the fleet's signing key, exactly as from GitHub. The hub applies the same check before it keeps a file, and keeps the last good copy when GitHub has a problem
* **onboarding:** **Administration → Onboarding** has a card showing what the hub holds, when it last copied from GitHub, and what went wrong if anything did
* **settings:** new setting **Settings → Fleet → Agent downloads through this hub**, on by default. Turning it off deletes the copy and sends every install to GitHub alone, as before

### Bug Fixes

* **agent install:** the Windows installer now checks the PawnIO driver installer against a pinned hash before running it. Before, it ran whatever another project's `master` branch served, unchecked. If the bytes do not match, the agent installs without PawnIO (no temperature or fan readings) instead of failing
* **agent install:** a failed PawnIO download no longer stops the Windows install

### Notes

* The hub needs to reach GitHub itself, and uses about 450 MB of disk under `logs/release_mirror`. The first copy is made a minute or two after the hub starts
* **Agents that are already installed still update from GitHub only.** Their own fallback to the hub comes with the next Windows and Linux agent releases. Until then, a PC that cannot reach GitHub stays on the version it was installed with
* To install by hand from the hub's copy, set `FLEETHUB_MIRROR_URL=https://<your hub>/api/agent/dist` before running `agent-install.ps1` or `install.sh`
* On an internet-facing hub the copy is served on the agent port, without sign-in, like the files on GitHub. Limit bandwidth at the reverse proxy if you need to

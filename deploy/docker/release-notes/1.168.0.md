## 1.168.0 (2026-10-27)

### Bug Fixes

* **inventory:** a machine whose agent has enrolled but never sent telemetry now appears in **Inventory** and on the **Dashboard**, online while it heartbeats. A Windows Sandbox and a cloud-GPU VM had enrolled, shown up as online agents and still been missing from both, because a machine was only listed once its first telemetry report arrived
* **telemetry:** the hub accepts a report with no temperature (`temp: null`), which is what a machine with no CPU temperature sensor -- any virtual machine -- has to send. Its identity, operating system, uptime and live load are recorded; it simply has no temperature, and no stored history charts
* **machine:** opening `/machine/<name>` for a name the hub has no record of shows **Machine not found** instead of an empty machine page that looked like a PC which had gone quiet
* **commands:** a command typed for a name no enrolled agent answers to is refused with a sentence saying so, instead of sitting *pending* until it expired. This covers the command channel and the Files tool; scheduled work (packages, patches, rules) is unchanged and still ends when the command expires

### Notes

* Windows shortens computer names longer than 15 characters, and the agent enrolls under the short name. A Windows Sandbox's name is a 36-character GUID, so it is listed as its first 15 characters (for example `035A185C-668A-4`).
* Machines without a temperature sensor send telemetry only from the next Windows agent release. Until then they are listed from their enrollment alone, without serial number, model or operating system.
* Enrollments that never reported anything are now visible too, so an old one may reappear in Inventory as offline. Delete it there if the machine is gone -- that also revokes its credential.

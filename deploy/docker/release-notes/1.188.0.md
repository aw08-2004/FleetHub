## 1.188.0 (2026-11-24)

### Features

* **listener:** the console can now stay off the internet while PCs outside the network keep reporting. Set `FLEETHUB_AGENT_PORT` (for example `29444`) and the hub opens a second listener that serves only the agent routes, the onboarding wizard, the Android APK download and the cross-hub sharing API, and answers `404` for everything else. Publish that port as your existing public address, and the console port only on an internal one
* **listener:** a new `CONSOLE_URL` setting names the internal address operators use. Sign-in callbacks, invite links and the assistant's links follow it. Left unset it is `HUB_URL`, so nothing changes on a hub that does not split

### Notes

* **Nothing changes until you set `FLEETHUB_AGENT_PORT`.** A hub that updates to this version serves exactly as before
* Agents need no change and no reinstall. They keep `HUB_URL`, which stays the public address
* To split, follow *Keeping the console off the internet* in `docs/installation.md`, in its order: set `CONSOLE_URL` and add its sign-in callback at Google or your OIDC provider **first**, then set `FLEETHUB_AGENT_PORT`, then point the public proxy at the new port. To roll back, point the proxy back at the console port
* After the split, the console, the desktop and mobile client and invite links work only on the LAN or over a VPN. That is the intended result
* The hub refuses to start if `FLEETHUB_AGENT_PORT` is not a port number or is the same as `FLEETHUB_PORT`. It does not fall back to one listener
* A Windows hub that still runs on port 3001 (waitress) must move to the HTTPS listener first, with `install.ps1 -MigrateHubServer`
* Once the Onboarding page lists no machines reporting without enrollment, turn on **Only accept telemetry from enrolled agents**. `/api/report` is one of the few routes the internet can still reach

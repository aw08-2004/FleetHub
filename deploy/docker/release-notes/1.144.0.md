## 1.144.0 (2026-10-12)

### ⚠ BREAKING CHANGES

* **telemetry:** the new setting **Settings → Security → Only accept telemetry from enrolled agents** ships **off**, so this image accepts telemetry exactly as before. Turning it on refuses every report that is not signed by an enrolled agent, and only Windows agent 3.44.0, Linux agent 0.4.0 and Android agent 0.3.0 or later sign. Before turning it on, open **Administration → Onboarding** and check that *Machines reporting without enrollment* is empty. Each machine listed there either needs its agent updated or needs to be onboarded with a code. Machines whose agent already signs are protected while the switch is off: their name will not accept unsigned reports.

### Features

* **onboarding:** one-time six-character codes under Administration → Onboarding, behind the new `manage_onboarding` capability (#119)
* **onboarding:** public `/onboarding` wizard that installs the agent and enrols the PC with its own credential, without the fleet enrollment secret (#119)
* **telemetry:** accept agent-signed reports on `/api/report`; a renamed PC keeps its enrollment, and another enrolled machine's name is refused (#119)
* **onboarding:** list the machines still sending unsigned telemetry (#119)

### Documentation

* **security:** document onboarding codes and signed telemetry in SECURITY.MD and the README (#119)

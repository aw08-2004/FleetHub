## 1.190.0 (2026-11-24)

### Features

* **remote:** remote view can now be **attended or unattended per OU or folder**. In **Group Policy**, add *Consent mode* to a policy and link it to an AD OU or a hub folder: the PCs under it ask the signed-in person to approve (attended) or connect at once (unattended), whatever the fleet-wide setting says. Link order, block inheritance and enforced links work as for every other policy setting, and a PC's Resultant Set of Policy shows which policy decided
* **remote:** a policy can also set *Allow remote view/control* to **off** for an OU or folder, for PCs nobody should be able to view. Starting a session on one is refused with a message naming Group Policy. The fleet-wide switch in **Settings → Remote Control** still wins: while it is off, no policy can turn remote back on
* **remote:** when a session is attended, the viewer now says it is waiting for the person at the PC to approve, instead of looking stuck
* **group policy:** the policy editor's *Agent settings* section is now called *Settings*, and the two remote settings carry an *Enforced by the hub* note

### Bug Fixes

* **settings:** the help for *Consent mode* no longer promises a per-machine override on the Remote tab that never existed; it points to Group Policy

### Notes

* Nothing to do for agents: the hub decides the mode when a session starts, and every agent already honours it
* A borrowed machine follows the policy of the hub that owns it

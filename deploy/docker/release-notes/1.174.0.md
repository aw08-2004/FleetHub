## 1.174.0 (2026-10-30)

### Features

* **group policy:** a policy can now set **User Configuration** -- the second half of the Local Group Policy Editor. In **Browse templates…**, *User Configuration* is no longer greyed: its settings are set exactly like Computer Configuration, and a setting gpedit lists in both halves can be set in each, separately
* **group policy:** typed registry values can be set in **HKCU** as well as HKLM: pick the hive at the start of the row, or paste a path that starts with `HKCU\`. Both are limited to `SOFTWARE\Policies`
* **group policy:** the resultant set of policy shows which half every setting and value belongs to (HKLM / HKCU, Computer / User Configuration)

### Notes

* **User Configuration applies to every user who signs in to the PC, administrators included**, as the local Group Policy Editor's User Configuration does. Windows applies it at each user's next sign-in, or within about 90 minutes for someone already signed in. *Applied* means the value is in the PC's local Group Policy, not that a given user has it yet
* **This needs Windows agent 3.49.** Deploy this hub first, as always. A PC on an older agent is not sent User Configuration values at all, and the resultant set shows *Needs agent 3.49 or newer* for them; its Computer Configuration is unaffected
* FleetHub cannot look inside each user's registry, so it does not report a domain policy overriding a User Configuration value. Settings somebody made in `gpedit.msc` under User Configuration are still left alone and reported as *managed elsewhere*
* Per-user and per-group local policies are not offered: a User Configuration setting reaches everyone who signs in to the PCs the policy applies to
* Uninstalling the agent takes FleetHub's values out of both halves of the local Group Policy

## 1.182.0 (2026-11-23)

### Bug Fixes

* **telemetry:** a hub with `AGENT_REPORT_SECRET` set no longer refuses every report ([#215](https://github.com/aw08-2004/FleetHub/issues/215)). No agent has ever sent that secret, so every machine on such a hub enrolled, took its config and showed no temperature, serial or uptime. The Docker template listed it as required, so every fresh Docker hub set up by the docs was affected. The hub now ignores the variable and says so in its log at startup; remove the line from `.env`. Identity on reports is signed telemetry's job (*Only accept telemetry from enrolled agents*) ([#216](https://github.com/aw08-2004/FleetHub/pull/216)) ([306e1bc](https://github.com/aw08-2004/FleetHub/commit/306e1bc))
* **remote:** signing in at the lock or logon screen no longer leaves a session relayed through the hub on a black screen ([#170](https://github.com/aw08-2004/FleetHub/issues/170)). Signing in replaces the agent's capture helper, and the replacement never heard that the session had moved to the relay. The viewer now tells it again, so the picture comes back on its own a few seconds after the sign-in. Works with the agents already installed ([#216](https://github.com/aw08-2004/FleetHub/pull/216)) ([264f81a](https://github.com/aw08-2004/FleetHub/commit/264f81a))
* **security:** Audit Log lines written before hub 1.176.0 no longer show a Remote session's TURN relay username and credential ([#199](https://github.com/aw08-2004/FleetHub/issues/199)). The hub removes them from those lines once at startup and hides them whenever a line is read. A borrowed machine's command status no longer passes them to the other hub either. Relay addresses stay visible, and the agent still receives what it needs ([#216](https://github.com/aw08-2004/FleetHub/pull/216)) ([efb5f66](https://github.com/aw08-2004/FleetHub/commit/efb5f66))

### Notes

* The agent half of #170 comes with Windows agent 3.53.0: a session started on the *logon screen* entry of the Session picker will then follow the sign-in into the new session, instead of staying on the logon screen. A session pinned to a signed-in user still stays where it was put
* Agent 3.53.0 also logs a report the hub refused as a warning with the hub's reason, instead of as "Sent"

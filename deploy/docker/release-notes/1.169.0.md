## 1.169.0 (2026-10-27)

### Features

* **terminal:** a Linux machine's **Terminal** tab is a real terminal when its agent is 0.4.0 or later: a login shell as root with keyboard input, Ctrl-C, Tab completion, full-screen programs like `top` and `vim`, resizing, and several tabs that survive leaving the page, the same as on a Windows PC. The shell box offers bash and sh. A Linux machine on an older agent keeps the one-shot script box, and its hint now says which agent version brings the terminal
* **palette:** **Ctrl+K** offers **Remote** beside Overview, Terminal, Files and Network. Pick a device, press → until Remote is highlighted, then Enter, and the Remote page opens with that PC already connecting. It is offered only to operators who can open the Remote page, and not on Linux or Android devices
* **onboarding:** a Linux machine can be onboarded with a code, the same as a Windows PC. On the install step of `/onboarding`, pick **Linux** and paste the one-line command into a terminal on the machine. It installs the agent (checked against the fleet's signed Linux manifest), then spends the code and saves the machine's own credential. The fleet-wide enrollment secret is not needed. Works with the current Linux agent, 0.3.0
* **machine:** the **Remote** button on a machine's page opens the Remote page connecting to that PC, instead of an empty picker

### Bug Fixes

* **terminal:** a machine that has enrolled but not yet reported an agent version, such as a Windows Sandbox, gets the real console instead of the old line-by-line terminal that could not answer prompts. If that machine's agent turns out to be too old to open one, the tab says so, in the agent's own words, instead of waiting at *Connecting*

### Notes

* Deploy this hub before cutting Linux agent 0.4.0. Under an older hub a 0.4.0 machine keeps the one-shot script box, because only this version's console switches a Linux machine to the real terminal.

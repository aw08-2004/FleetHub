## 1.145.0 (2026-10-12)

### Features

* **agent install:** a fresh agent install registers its Windows service as `FleetHubAgent` instead of `TempMonitorAgent`. An existing install migrates only when `agent-install.ps1` runs on it again (a technician, `install.ps1` or onboarding), in this order: stop the old service, create the new one with its recovery actions, delete the old one, start the new one. A failed registration restarts the old service and stops. Self-update does not migrate a PC, and does not need to (#120) (270fb3c) (443f2af)
* **watchdogs:** the hub refuses to restart the agent's own service under either name, so a watchdog cannot be aimed at `FleetHubAgent` or at `TempMonitorAgent` on a PC not yet migrated (#120) (270fb3c)

### Documentation

* The fleet is allowed to stay mixed: a PC nobody re-installs stays `TempMonitorAgent`, and anything naming the service must accept both. The reasoning and the alternatives rejected are in ROADMAP.MD, *Agent service renamed to `FleetHubAgent`*.

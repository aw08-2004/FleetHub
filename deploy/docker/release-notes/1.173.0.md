## 1.173.0 (2026-10-30)

### Features

* **group policy:** registry values and template settings now go into each PC's **local Group Policy** instead of straight into the registry. `gpedit.msc` on the PC shows them as configured, `gpresult` lists them under Local Group Policy, and Windows itself writes and removes the values. A domain policy that sets the same value still wins, as it does for any local policy
* **group policy:** a **Disabled** template setting now also deletes the values Windows deletes for it, as `gpedit.msc` does
* **group policy:** the resultant set of policy says whether a PC's agent writes its local Group Policy or, for an older agent, the registry directly, and shows a deleted value as **Deleted**

### Notes

* **This needs Windows agent 3.50.** Deploy this hub first, as always; until a PC runs agent 3.50 it keeps writing the registry directly and ignores deletes, and the resultant set says so for that PC
* **Nothing moves on a PC until its agent updates.** Agent 3.50 moves the values an older agent wrote into the local Group Policy, with the same data, so nothing a user sees changes
* Settings somebody made in `gpedit.msc` on the PC are left alone, exactly like values a domain policy or Intune set: FleetHub reports them as *managed elsewhere* and never overwrites them. Changing a FleetHub setting in `gpedit.msc` hands it over to the PC in the same way
* When a domain policy overrides a FleetHub value, the PC reports it as *managed elsewhere* a few minutes after the change. The FleetHub value stays in the local Group Policy and takes effect again if the domain policy goes
* Uninstalling the agent, from the console or with `agent-install.ps1 -Uninstall`, takes FleetHub's values out of the local Group Policy and leaves everything else in it as it was

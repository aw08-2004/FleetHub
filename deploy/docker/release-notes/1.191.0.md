## 1.191.0 (2026-11-26)

### Bug Fixes

* **backups:** **Test connection** on an S3 destination now also checks the pre-signed upload links the PCs use. Before, the test could pass while every PC file backup then failed within seconds with *Upload failed: Error while copying content to a stream*. The test now fails instead, with a message that says the destination rejects the PCs' upload links
* **backups:** when the destination answers that check with `SignatureDoesNotMatch`, the message names the most common cause: an access key entered in the wrong case. MinIO AIStor stores keys in lowercase and accepts the hub's own requests whatever the case, but not the PCs' links. Re-enter the key exactly as the storage server shows it

### Notes

* Nothing to do for agents
* If your PC file backups fail with *Error while copying content to a stream*, open the destination under **Fleet tasks → Backup** and press **Test connection** after updating
* The hub does not change the case of your access key for you: AWS keys are uppercase and case-significant

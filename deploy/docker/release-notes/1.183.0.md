## 1.183.0 (2026-11-23)

### Features

* **packages:** the deployment view now shows each machine's live status: *Queued*, *Sent, waiting for the machine*, *Running*, *Aborting…*, *Waiting to retry* and the final result. While a machine runs it shows which step it is on (*Step 2 of 3 · Install drivers*) and for how long ([#217](https://github.com/aw08-2004/FleetHub/pull/217))
* **packages:** click a machine to see its whole step list: each download, each step and the detection check, with its result, exit code and duration. A failed step says why next to the machine (*Failed at Step 2 · Install drivers*) ([#217](https://github.com/aw08-2004/FleetHub/pull/217))
* **packages:** *Log* under a step shows that step's own output, and it follows along while the step is still running ([#217](https://github.com/aw08-2004/FleetHub/pull/217))
* **packages:** select machines in the deployment view to **Abort** them, including ones installing right now. A machine that has not started is cancelled at once. One that is installing stops at its current step within about ten seconds, and the row reads *Aborting…* until it has. An aborted machine is not retried ([#217](https://github.com/aw08-2004/FleetHub/pull/217))
* **packages:** **Redeploy** the selected machines, including ones where the package already succeeded, and **Retry now** to skip a failed machine's retry wait. *Retry failures* now only retries the machines you can see ([#217](https://github.com/aw08-2004/FleetHub/pull/217))
* **packages:** a new deployment, a retry, an abort and a machine's result now take effect within a second, not on the scheduler's next half-minute pass ([#217](https://github.com/aw08-2004/FleetHub/pull/217))

### Notes

* The step view and Abort need **Windows agent 3.53.0**. Machines on an older agent install exactly as before, show as *Running* with their planned steps, and cannot be aborted mid-install; the view says so. Deploy this hub before the agent
* A step's log is kept as long as the command output setting keeps it (24 hours by default). After that the log says it has been cleaned up, and the machine's command history still has the whole run

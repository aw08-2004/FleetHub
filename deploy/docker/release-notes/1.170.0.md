## 1.170.0 (2026-10-28)

### Features

* **hub:** a **new** hub install serves **HTTPS on port 29443**, instead of plain HTTP on 3001. The tunnel or proxy in front stays, but its connection to the hub is now encrypted too. Port 3001 belongs to another product in the IANA registry; 29443 is unassigned there
* **hub:** the hub makes its own self-signed certificate on first start, under `tls\` in the hub's install folder (`/state/tls/` in Docker). To use your own certificate instead, put the PEM files there as `hub.crt` and `hub.key`, or point `FLEETHUB_TLS_CERT` and `FLEETHUB_TLS_KEY` in `.env` at them. The hub never overwrites a certificate that is already there
* **installer:** `install.ps1 -MigrateHubServer` moves an existing hub from 3001 to HTTPS on 29443. `-HubTlsCert` and `-HubTlsKey` install your own certificate in the same run

### Notes

* **Existing hubs do not change.** This update keeps a hub that runs on 3001 running on 3001, over plain HTTP, exactly as before. Nothing in the tunnel, the proxy or the agents needs to change
* **If you migrate a hub, change the tunnel or proxy in the same step**, or the console goes dark:
  * Cloudflare tunnel: set the service to `https://localhost:29443` and turn on **No TLS Verify** (or set **Origin Server Name** and trust the hub's certificate)
  * nginx: `proxy_pass https://127.0.0.1:29443;` (add `proxy_ssl_verify off;`, or `proxy_ssl_trusted_certificate` pointing at the hub's `hub.crt`)
* Agents and the desktop client need no change. They connect to the public hub address, not to the port behind the proxy
* This update installs one new Python package, `cheroot`. A hub that cannot reach the Python package index holds this update back until it can
* Docker: the image still listens on 3001 over plain HTTP unless your compose file says otherwise, so an existing compose file keeps working. The shipped `compose.yaml` now sets `FLEETHUB_PORT=29443` and `FLEETHUB_TLS=1` for new deployments

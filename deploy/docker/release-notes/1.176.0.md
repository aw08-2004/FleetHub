## 1.176.0 (2026-11-02)

### Features

* **onboarding:** a PC that was enrolled before can be onboarded again under its own name without deleting its record first, even when its BIOS serial is a placeholder (*To Be Filled By O.E.M.*, *Default string*) -- the usual case is a re-imaged whitebox whose old agent was revoked. The hub now records each machine's SMBIOS UUID and Windows MachineGuid (`/etc/machine-id` on Linux) beside its serial, and onboarding compares them. A re-imaged PC still matches on its hardware. A different PC under the same name is still refused, as before
* **agents:** the next Windows and Linux agents report the SMBIOS UUID and MachineGuid / machine-id

### Bug Fixes

* **security:** a remote session's TURN relay username and credential no longer reach operators who can only view the machine or read the Audit Log (#199). Both the command's own page (`/api/fleet/commands/<id>`) and its *issue_command* audit line now show the relay addresses only. The agent still receives the credential it needs

### Notes

* The identifiers are recorded only from enrolled agents' signed reports and from a successful onboarding, never from an unsigned report: on a hub that accepts unsigned telemetry, anybody could otherwise be first to claim a name's identity. A PC that has only ever reported unsigned is therefore treated as before until it has been onboarded once
* Audit lines written before this version still contain the credentials they were written with. Minted TURN credentials expire on their own; if you pasted a long-lived *Provided ICE servers* block, generate a new one

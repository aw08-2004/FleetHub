## 0.3.1 (2026-10-23)

This agent has its own 0.x version line. It is not behind the Windows agent's 3.x.

### Bug Fixes

* **provisioning:** a phone provisioned with the hub's QR code now enrolls by itself. Until now the app threw away the hub URL and enrollment secret the QR carries, so after a factory reset and a scan the device came up as device owner but opened on the setup screen and asked for the hub URL, and had to be onboarded by hand. Nothing changes on the hub and the QR codes you have already printed keep working. Android hands this configuration over in a form the app was not reading, and the read failed without an error, so the device looked like it had been provisioned without any configuration.

### What the person holding the device sees

* Nothing new. The setup screen no longer appears after QR provisioning, because there is nothing left for anyone to type.

### What to do

* **Upload the 0.3.1 APK on the hub's *Android device provisioning* page (Agent APK).** A factory-reset phone installs whichever APK the hub is serving, not the newest release. A hub still serving an older APK keeps producing phones that ask for the hub URL.
* Devices that were already onboarded by hand need nothing. The fix only matters at provisioning time, so it shows on the next phone you factory-reset and scan.
* To check that it worked, run `adb logcat -s FleetHubAgent` during provisioning. It should print *Adopted hub URL from the QR* and *Adopted the enrollment secret from the QR*.

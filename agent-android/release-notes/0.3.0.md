## 0.3.0 (unreleased)

### ⚠ BREAKING CHANGES

* **location:** a device that is not fully managed needs one manual step after it takes this update: open the FleetHub Agent app and press *Grant location*, or a locate from the console keeps answering "unavailable". A device that is not a device owner cannot update itself silently, so install 0.3.0 over the top with `adb install -r` first. A fully managed device needs nothing: it updates silently and grants itself the permission the first time somebody locates it ([#64](https://github.com/aw08-2004/Temp_Monitor/pull/64)) ([0fe50b7](https://github.com/aw08-2004/Temp_Monitor/commit/0fe50b7))
* **rollout:** deploy hub 1.144.0 or later before relying on signed telemetry. An older hub ignores the new `Authorization` header on `/api/report`, so updating the phones first is harmless, but Settings → Endpoint Security → *Only accept telemetry from enrolled agents* must stay off until every agent in the fleet signs, which also waits on Linux 0.4.0 ([#119](https://github.com/aw08-2004/Temp_Monitor/pull/119)) ([cdc939f](https://github.com/aw08-2004/Temp_Monitor/commit/cdc939f))

### Features

* **messages:** a notice sent from the console or a rule now reaches the phone as a heads-up notification with up to three answer buttons, and the person's answer is reported back so the rule's follow-up actions fire. Swiping the notice away is reported as *dismissed*; a message with no timeout waits one hour; with notifications switched off for the agent it comes back *no session* with the reason. A message with four buttons comes back as a failure naming the limit. Nothing is collected beyond which button was pressed ([#72](https://github.com/aw08-2004/Temp_Monitor/pull/72)) ([ba1c4d3](https://github.com/aw08-2004/Temp_Monitor/commit/ba1c4d3))
* **telemetry:** sign every report with the device's own agent token, so another device can no longer report under this device's name ([#119](https://github.com/aw08-2004/Temp_Monitor/pull/119)) ([cdc939f](https://github.com/aw08-2004/Temp_Monitor/commit/cdc939f))

### Bug Fixes

* **location:** ask for the location permission, which no earlier release ever did, so a locate no longer answers "the location permission has not been granted" on every device. Approximate location is enough; the console shows the accuracy it actually had. The agent still never asks for background location, and the device still shows a notification naming the operator every time, whether or not a position is found. If the permission has been refused twice, Android stops offering the dialog and the button opens the app's settings page instead ([#64](https://github.com/aw08-2004/Temp_Monitor/pull/64)) ([0fe50b7](https://github.com/aw08-2004/Temp_Monitor/commit/0fe50b7))
* **location:** the setup screen now says whether location is granted, and a locate that cannot answer says what to do about it, telling a device waiting for somebody to grant the permission apart from a fully managed device that would not grant it itself (a provisioning problem) ([#64](https://github.com/aw08-2004/Temp_Monitor/pull/64)) ([0fe50b7](https://github.com/aw08-2004/Temp_Monitor/commit/0fe50b7))
* **messages:** stop one message's cleanup pulling another message's notification off the screen ([#72](https://github.com/aw08-2004/Temp_Monitor/pull/72)) ([8cfbefc](https://github.com/aw08-2004/Temp_Monitor/commit/8cfbefc))

### Code Refactoring

* **commands:** run up to four commands at once instead of two, because a message waiting on an answer occupies a slot for as long as the person takes and two of those would have left a device accepting nothing else ([#72](https://github.com/aw08-2004/Temp_Monitor/pull/72)) ([ba1c4d3](https://github.com/aw08-2004/Temp_Monitor/commit/ba1c4d3))

### Documentation

* The signing certificate is unchanged, so printed provisioning codes stay valid and 0.3.0 installs over 0.2.3 in place. This agent is on its own `0.x` line and is not behind the Windows agent's `3.x`.
* **Neither half of locating or messaging has been run on a real phone.** Both were written against the platform documentation and type-checked against Android's reference assembly, and the test suite covers what a workstation can check. No device has been watched granting the permission, returning a fix, or showing a message and reporting which button was pressed. Treat the first device you update as the one that proves it. To watch one: `adb logcat -s FleetHubAgent:*`.

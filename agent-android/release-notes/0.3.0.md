## 0.3.0 (2026-10-20)

This agent has its own 0.x version line. It is not behind the Windows agent's 3.x.

### ⚠ BREAKING CHANGES

* **rollout:** deploy hub **1.158.0 first**. On an older hub, an APK package and the phone posture checks have nothing to land in. A device that is not fully managed cannot update itself without somebody at it: install 0.3.0 over the top (`adb install -r`), then open the app.

### Features

* **enrollment:** enroll a phone with a **one-time code** from Administration → Onboarding instead of the fleet-wide secret. The code admits this device once and is worthless afterwards. The shared secret still works, under *Advanced*, for devices whose MDM pushes it
* **app:** a new home screen. It opens on the device's status (managed, not enrolled, offline), followed by a setup checklist: enrollment, location, notifications, battery optimisation, usage access and device owner. Each row says what goes wrong without it and has the button that fixes it. No text field or keyboard appears when the app opens
* **app:** the FleetHub icon on the launcher (adaptive and themed icons included) and in the status bar, replacing the default Android icon and the sync arrows
* **locate:** the app asks for the location permission, which no earlier release ever did. Before this, every Locate answered *the location permission has not been granted on this device*, so no phone ever appeared on the map. A fully managed device grants it to itself the first time somebody locates it. Every other device needs *Grant location* on the setup screen
* **messages:** `show_message` reaches a phone as a notification with up to three buttons, and the answer comes back to the console and the rules engine exactly as it does from a PC. Swiping the notice away comes back as *dismissed*. A message with no timeout waits one hour
* **restart:** fully managed devices can be restarted from the console and from rules. The command answers first and the device restarts five seconds later at the earliest. A device that is not fully managed refuses, and says why
* **packages:** fully managed devices install apps deployed from **Packages** with the new *Install an Android app* step. Each APK is checked against its sha256 pin and installed silently. Success is reported only once Android confirms the app is installed at the version the APK declares. An install Android does not answer within the step's timeout, or that stops to wait for somebody to tap, is cancelled and reported failed, so the app cannot turn up later. Payloads over 512 MB are refused, and the agent's hub credential is sent only to the hub itself, never to a CDN a download redirects to. The agent refuses to install itself this way; it updates only through its own signed release channel
* **wake:** a phone on the office Wi-Fi can relay **Wake-on-LAN** for a sleeping PC on the same subnet, like an awake PC does. Only fully managed phones are picked as relays, because only a device owner can read the device's real MAC address. Some Wi-Fi access points drop broadcast frames between clients, so a relayed wake is confirmed by the PC checking in, never by the packet leaving
* **network:** fully managed phones report their Wi-Fi adapter (address, subnet, MAC) to the console's Network tab
* **posture:** phones report screen lock, storage encryption and security patch level, and the Security posture card judges them on those three checks (CIS 4.3, 3.6, 7.3)

### What the person holding the device sees

* **Locating:** nothing is collected in the background and there is no location history. A position is read only when an operator presses Locate, and a notification naming that operator appears every time, whether or not a position is found
* **Restart and app installs:** these happen without a prompt on a fully managed device, which is what device ownership means. Neither is possible on a device that is not fully managed
* **Messages:** a notification with buttons, not a dialog over whatever the person is doing

### Bug Fixes

* **locate:** a phone that could not answer a locate now says why on the setup screen. The console's map lists it with that reason instead of leaving it out
* **dispatcher:** `restart` and `deploy_package` are no longer refused as impossible on Android. `install_app` now points at an APK package, and `shutdown` at restart

Not yet run on a real phone: everything above was compiled against Android's reference assemblies and covered by the agent's workstation tests, but treat the first device you update as the one that proves it.

The agent logs to logcat under the tag `FleetHubAgent`:

```bash
adb logcat -s FleetHubAgent:*
```

## 3.47.0 (2026-10-20)

### ⚠ BREAKING CHANGES

* **rollout:** deploy hub 1.155.0 or later before this agent. This release rolls up everything since 3.44.0, so it needs the newest of the hub versions the steps in between asked for: the ticket tray files tickets and fetches *My tickets* through agent routes that exist from hub 1.152.0, the remote viewer's clipboard controls ship with 1.153.0, and the new Windows Update control is driven by 1.155.0. An agent running ahead of its hub is harmless -- the tray stays off, the viewer never offers a paste, and no PC is sent the update-control command -- but the new features do nothing until the hub is deployed ([#146](https://github.com/aw08-2004/FleetHub/pull/146)) ([ae291a1](https://github.com/aw08-2004/FleetHub/commit/ae291a1))
* **installer:** the release asset is now `FleetHubAgent.exe`, not `TempMonitorAgent.exe`. Self-update writes the new build over whatever path a PC already runs, so existing PCs keep `TempMonitorAgent.exe` until `agent-install.ps1` is re-run on them; the installer re-points the service at the new exe and only then removes the old one. Anything outside this repo that downloads the exe by its old asset name has to be changed ([#129](https://github.com/aw08-2004/FleetHub/pull/129)) ([5d31c5d](https://github.com/aw08-2004/FleetHub/commit/5d31c5d))
* **patches:** nothing changes on a PC until someone ticks *Only FleetHub installs updates on these machines* on a maintenance window. When that is ticked, the PC stops installing Windows updates by itself and Settings loses its *Install* button, so only approved updates installed during a patch run reach it. Leave it off on any window whose PCs you do not want to take Windows Update away from ([#157](https://github.com/aw08-2004/FleetHub/pull/157)) ([aa95ee5](https://github.com/aw08-2004/FleetHub/commit/aa95ee5))

### Features

* **patches:** take Windows Update over on request. The agent turns off Windows' own automatic updates and hides *Install* in Settings, so an approved update lands on a patch run rather than whenever Windows or the person at the PC chose, and a declined update can no longer install by itself ([#157](https://github.com/aw08-2004/FleetHub/pull/157)) ([aa95ee5](https://github.com/aw08-2004/FleetHub/commit/aa95ee5))
* **patches:** leave alone a PC whose Windows Update is set by Group Policy or Intune. The agent writes only values it did not find already set, reports the PC as managed elsewhere, and the hub skips it ([#157](https://github.com/aw08-2004/FleetHub/pull/157)) ([aa95ee5](https://github.com/aw08-2004/FleetHub/commit/aa95ee5))
* **patches:** hand control back cleanly. Switching the option off, deleting the device with *also uninstall the agent* ticked, and `agent-install.ps1 -Uninstall` each remove only the values FleetHub wrote, so an uninstalled agent never leaves a PC that nobody patches, and a policy that has since taken a value over keeps it ([#157](https://github.com/aw08-2004/FleetHub/pull/157)) ([aa95ee5](https://github.com/aw08-2004/FleetHub/commit/aa95ee5))
* **patches:** report who installs updates on each PC, and every update from the last 30 days that Windows Update history credits to something other than FleetHub (Defender definition updates left out), so a local administrator who deletes the policy keys is noticed and taken back on the next pass ([#157](https://github.com/aw08-2004/FleetHub/pull/157)) ([aa95ee5](https://github.com/aw08-2004/FleetHub/commit/aa95ee5))
* **tickets:** let the person signed in at a PC open a ticket from a tray icon, with a screenshot of every screen they can untick before sending, and see the helpdesk's replies under *My tickets* with a notification; they can answer from the tray, which re-opens a waiting or resolved ticket. The tray stays off until Settings → Tickets → *Keep the ticket tray running on PCs* is switched on, so the update itself changes nothing a person at a PC sees ([#146](https://github.com/aw08-2004/FleetHub/pull/146)) ([ae291a1](https://github.com/aw08-2004/FleetHub/commit/ae291a1))
* **tickets:** file every ticket as the Windows account actually connected to the service, never as whoever the tray claims to be; the tray never holds the agent token, and a local account sees no *Report a problem* when Settings → Tickets allows domain accounts only ([#146](https://github.com/aw08-2004/FleetHub/pull/146)) ([ae291a1](https://github.com/aw08-2004/FleetHub/commit/ae291a1))
* **tickets:** limit each person to 5 tickets, 20 replies and 60 *My tickets* refreshes per ten minutes; a refused refresh says so instead of emptying the list ([#146](https://github.com/aw08-2004/FleetHub/pull/146)) ([90e4bcf](https://github.com/aw08-2004/FleetHub/commit/90e4bcf))
* **tickets:** keep one tray per signed-in session while the setting is on, stop relaunching a tray that dies more than 5 times in an hour, and replace it with the new build on self-update unless a ticket window is open ([#146](https://github.com/aw08-2004/FleetHub/pull/146)) ([ae291a1](https://github.com/aw08-2004/FleetHub/commit/ae291a1))
* **remote:** carry text clipboard both ways during a remote session: a copy on the PC lands on the operator's own clipboard (or behind *Copy from PC* where the browser wants a click), and Ctrl+V on the picture sends the operator's clipboard first so the PC pastes the new text; works over WebRTC and the hub relay, up to 65,536 characters each way, and says so when longer text is cut. Gated on the existing `remote_control` permission, so nothing new has to be granted ([#150](https://github.com/aw08-2004/FleetHub/pull/150)) ([c70e93e](https://github.com/aw08-2004/FleetHub/commit/c70e93e))
* **remote:** add *Send Cmd as Ctrl*, on by default from a Mac, so Cmd+C and Cmd+V reach the PC as Ctrl+C and Ctrl+V instead of Win+C and Win+V ([#150](https://github.com/aw08-2004/FleetHub/pull/150)) ([c70e93e](https://github.com/aw08-2004/FleetHub/commit/c70e93e))
* **capabilities:** report a capabilities block (`processes`, `ticketing`) for the first time; it lists features only, never commands, so no console button disappears ([#146](https://github.com/aw08-2004/FleetHub/pull/146)) ([ae291a1](https://github.com/aw08-2004/FleetHub/commit/ae291a1))
* **service:** build the agent as `FleetHubAgent.exe`, give it the FleetHub logo (which the ticket tray also takes its icon from), and refuse to end either `FleetHubAgent.exe` or `TempMonitorAgent.exe` from the process list ([#129](https://github.com/aw08-2004/FleetHub/pull/129)) ([5d31c5d](https://github.com/aw08-2004/FleetHub/commit/5d31c5d)) ([#149](https://github.com/aw08-2004/FleetHub/pull/149)) ([e47b2ab](https://github.com/aw08-2004/FleetHub/commit/e47b2ab))

### Bug Fixes

* **tickets:** ticket screenshots reach the hub. Every ticket from the tray arrived with "0/N screenshot(s)" and `Host desconocido` / `No such host is known` in the agent log, while the name resolved fine everywhere: the service was reading the person's account name in a way that left their limited sign-in token on the whole tray connection, and with that token it could not look up the hub's name for a new connection. A failed screenshot upload is also logged now as a warning with its network cause. Fixes [#153](https://github.com/aw08-2004/FleetHub/issues/153) ([#159](https://github.com/aw08-2004/FleetHub/pull/159)) ([e18de88](https://github.com/aw08-2004/FleetHub/commit/e18de88)) ([#154](https://github.com/aw08-2004/FleetHub/pull/154)) ([9c984c2](https://github.com/aw08-2004/FleetHub/commit/9c984c2))

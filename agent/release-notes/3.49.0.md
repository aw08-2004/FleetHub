## 3.49.0 (2026-10-30)

### ⚠ BREAKING CHANGES

* **rollout:** deploy hub 1.174.0 or later before this agent; on the beta channel that is the hub built from the `beta` branch. Everything new below is driven by the hub: an agent running ahead of its hub uploads no templates, receives no User Configuration and honours no pin, and otherwise behaves as 3.48 did
* **group-policy:** Group Policy registry values now go into each PC's **local Group Policy** (`C:\Windows\System32\GroupPolicy`) instead of straight into the registry, and Windows applies them. On the first run after this update the agent moves the values an older agent wrote into the local Group Policy with the same data, so nothing a user sees changes. Expect `gpedit.msc` and `gpresult` on your PCs to show FleetHub's settings from now on ([#192](https://github.com/aw08-2004/FleetHub/pull/192)) ([ba7c3a2](https://github.com/aw08-2004/FleetHub/commit/ba7c3a2))
* **group-policy:** **User Configuration applies to every user who signs in to a PC, administrators included.** Nothing changes until a policy with User Configuration settings is linked above a PC. Link a new one to one OU or hub folder of test PCs first, sign in there as a standard user, and check **Resultant set of policy** before linking it any wider

### Features

* **group-policy:** send this PC's Administrative Templates (`C:\Windows\PolicyDefinitions`, with their English, German and Spanish texts) when the hub asks, so the console's **Browse templates…** shows the settings your PCs actually have. The hub asks one PC per Windows build, once ([#191](https://github.com/aw08-2004/FleetHub/pull/191)) ([3768ea0](https://github.com/aw08-2004/FleetHub/commit/3768ea0))
* **group-policy:** write Computer Configuration into the local Group Policy's `Machine\Registry.pol` and ask Windows to apply it at once. `gpedit.msc` on the PC shows the settings as configured, `gpresult` lists them under Local Group Policy, and Windows removes a value itself when its policy stops applying. A domain policy that sets the same value is applied after the local one and still wins; the PC reports it as **Managed elsewhere** a few minutes after the change, and the FleetHub value takes effect again if the domain policy goes ([#192](https://github.com/aw08-2004/FleetHub/pull/192)) ([ba7c3a2](https://github.com/aw08-2004/FleetHub/commit/ba7c3a2))
* **group-policy:** apply **User Configuration** (HKCU), written into the local Group Policy's `User\Registry.pol`. Windows applies it to each user at their next sign-in, or within about 90 minutes for someone already signed in. A PC with no User Configuration never reads or touches that file
* **group-policy:** carry out a **Disabled** template setting's deletes, as `gpedit.msc` does, so the value it deletes is gone from the PC and the setting reads *Disabled* in gpedit ([#192](https://github.com/aw08-2004/FleetHub/pull/192)) ([ba7c3a2](https://github.com/aw08-2004/FleetHub/commit/ba7c3a2))
* **group-policy:** leave alone a setting somebody made in `gpedit.msc` on the PC, exactly like one a domain policy or Intune set, and report it as **Managed elsewhere**. A FleetHub setting changed in gpedit is handed over to the PC rather than fought; one set back to *Not configured* there is put back. Every entry of the local Group Policy that FleetHub did not write is kept byte for byte, and a local Group Policy file the agent cannot read is reported as an error and never rewritten ([#192](https://github.com/aw08-2004/FleetHub/pull/192)) ([ba7c3a2](https://github.com/aw08-2004/FleetHub/commit/ba7c3a2))
* **group-policy:** report a Computer value that is in the local Group Policy but that Windows has not applied (local policy processing switched off by a domain policy, for example) as an **Error**, and force at most one policy refresh an hour to try again ([#192](https://github.com/aw08-2004/FleetHub/pull/192)) ([ba7c3a2](https://github.com/aw08-2004/FleetHub/commit/ba7c3a2))
* **fleet:** honour a **version pin** for Windows agent updates (**Settings → Fleet**): a pinned PC installs exactly the pinned version, forward or back, and nothing newer. A pin at the running version turns automatic updates off until it is raised. The pin is remembered across restarts, so a PC that boots before reaching the hub keeps it ([#177](https://github.com/aw08-2004/FleetHub/pull/177)) ([a6c610a](https://github.com/aw08-2004/FleetHub/commit/a6c610a))
* **telemetry:** report from a machine with no CPU temperature sensor -- any virtual machine, a Windows Sandbox -- with no temperature, instead of sending nothing, so it is listed in **Inventory** with its serial number, model and operating system ([#182](https://github.com/aw08-2004/FleetHub/pull/182)) ([46f304c](https://github.com/aw08-2004/FleetHub/commit/46f304c))

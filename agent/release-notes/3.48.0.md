## 3.48.0 (2026-10-22)

### ⚠ BREAKING CHANGES

* **rollout:** deploy hub 1.159.0 or later before this agent; on the beta channel that is the hub built from the `beta` branch. The hub is what sends each PC its Group Policy registry values. An agent running ahead of its hub only reports that it can apply them, and writes nothing ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))
* **group-policy:** nothing changes on a PC until a policy with registry values is linked above it. Once one is, every PC beneath that node gets its values within about two minutes, with nobody at the PC. Link a new policy to one OU or hub folder of test PCs first, and check **Resultant set of policy** for one of them before linking it any wider ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))

### Features

* **group-policy:** apply the registry values Group Policy sets for this PC: DWORD, string, expandable-string and multi-string values under `HKLM\SOFTWARE\Policies`. The PC checks them every minute and keeps its policy across restarts, so a PC that boots without a network still has it. Agent settings and scripts in a policy need no agent update; only registry values need this release ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))
* **group-policy:** never overwrite a value FleetHub did not write. A value already set by a domain GPO, Intune or a person is left alone and shown as **Managed elsewhere**. A value FleetHub set that something else later changes is let go rather than fought, so the agent never flips a setting back after `gpupdate`. A value somebody simply deletes is put back ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))
* **group-policy:** remove the values a policy set when it is unlinked, disabled or deleted, as long as each still holds what FleetHub wrote ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))
* **group-policy:** refuse, on the PC itself, any value outside `HKLM\SOFTWARE\Policies`, under Windows Update policy, or under FleetHub's own key, whatever the hub sends. Such a value is shown as **Refused by the agent** ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))
* **group-policy:** report each value as **Applied**, **Managed elsewhere**, **Error** or **Refused by the agent** in **Resultant set of policy**. A report is kept and sent again until the hub confirms it stored it, so a dropped heartbeat cannot lose one ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))
* **uninstall:** remove the Group Policy values the agent wrote, and its marker key `HKLM\SOFTWARE\FleetHub\GroupPolicy`, when the device is deleted with *also uninstall the agent* ticked and when `agent-install.ps1 -Uninstall` is run ([#163](https://github.com/aw08-2004/FleetHub/pull/163)) ([48a7e70](https://github.com/aw08-2004/FleetHub/commit/48a7e70))

## 3.51.0 (2026-11-15)

### ⚠ BREAKING CHANGES

* **rollout:** deploy hub 1.179.0 or later before this agent. An agent running ahead of its hub is harmless: nothing asks it to copy a folder until the hub offers *Send to another computer*, and the hub only offers it once both PCs report 3.51.0 ([#207](https://github.com/aw08-2004/FleetHub/pull/207)) ([b27d828](https://github.com/aw08-2004/FleetHub/commit/b27d828))

### Features

* **files:** send folders live to another PC through the hub when an operator chooses *Send to another computer…* in the Files tab. Files are read while in use where Windows allows it; one held open exclusively (an Outlook .pst in use) is skipped and named in the command output, and junctions are never followed. Nothing on this PC changes ([#207](https://github.com/aw08-2004/FleetHub/pull/207)) ([b27d828](https://github.com/aw08-2004/FleetHub/commit/b27d828))
* **files:** receive a folder copy from another PC into the folder the operator picked. Each file is written as `*.fhpart` and renamed only once it is complete, so a copy cut off part way leaves no truncated file. Files already there are kept, not replaced, and a path that would land outside the chosen folder, or through a link out of it, is refused and counted in the result ([#207](https://github.com/aw08-2004/FleetHub/pull/207)) ([b27d828](https://github.com/aw08-2004/FleetHub/commit/b27d828))
